## Hard rules derived from the capability block above
- If `is_git_repo: False`, you are FORBIDDEN from using any `git` subcommand in `required_tests`, `success_criteria`, or `rollback_plan` other than as a comment. `git diff`, `git diff --name-only`, `git status`, `git log`, `git rev-parse`, `git ls-files`, `git show`, `git stash` will all exit 129 in this workdir and the validator will reject every retry. Use direct verifications instead: `test -f path`, `grep -q PATTERN path`, `cmp old.txt new.txt`, `python3 -c "..."`, `python3 -m pytest path::test`, `[ "$(wc -l < path)" = "N" ]`.
- For rollback in non-git workdirs, use direct file commands (`rm -f`, `mv backup orig`) instead of `git checkout`.
- If `recommended_python_invocation: python3`, prefer `python3` over bare `python` everywhere. Bare `python` is not guaranteed to exist and will exit 127.
- If `has_pytest_executable: False` but `has_pytest_via_python3_m: True`, use `python3 -m pytest` instead of bare `pytest`.
- If `has_diff: False`, do not use `diff`. Substitute with `cmp` (if available) or a `python3 -c` byte comparison.
- If a tool you need is not in the capability block, it is not available — choose a different verification.

Every command in `required_tests` must be a command this environment can actually run. A test that exits non-zero solely because the tool is missing is a contract bug, not Codex's fault, and the run will abort.
